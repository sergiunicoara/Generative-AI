# Implementation Audit

**Date:** 2026-09-21 (reconciled with the current tree); **updated 2026-09-22** after closing 5 backlog items and fixing a critical live cross-tenant leak found while implementing them (see `tasks/lessons.md` A174).
**Method:** Four parallel code-and-test audits (tenant/opportunity isolation; MCP/agent security + prompt injection; provenance/temporal/contradiction/entity-resolution; retrieval/eval/observability/cost), each verifying claims against actual source and test files with `file:line` evidence — never against README, roadmap, or comments. Baseline tests were not re-run as part of this audit pass; existing automotive/aerospace eval baselines from this session (`tasks/automotive-retrieval-diagnosis-report.md`) remain the most recent recorded results.

**2026-09-22 addendum — a critical finding this audit's own methodology missed:** building the live retrieval-path tenant-isolation test recommended below (former backlog item #3) surfaced a real, live cross-tenant data leak in `vector_search_chunks` (default path), `bm25_search_chunks`, and `bm25_search_entities` — confirmed by direct reproduction, not inference. Root cause: `OPTIONAL MATCH (c)-[:PART_OF]->(d:Document) WHERE (c.tenant = $tenant) AND ...` — Cypher binds a `WHERE` immediately after `OPTIONAL MATCH` to the *match's* pattern predicate, not to the row; a failing predicate nulls the optional variable instead of dropping the row, so `c.tenant = $tenant` (and `is_deleted`, bitemporal, and ACL checks in the same clause) never filtered anything. This means several rows below in this table that were rated "Implemented" or graded on query-shape test coverage were **wrong in a way this audit's own stated method — verifying against `file:line` evidence — did not catch**, because the evidence was Cypher text that *looked* correct, not a live query result. Fixed (see row-level notes below) by inserting `WITH <vars>` between `OPTIONAL MATCH` and `WHERE`, restoring normal row-filtering semantics; verified live before/after. Full detail and the general rule (audit any other `OPTIONAL MATCH` immediately followed by `WHERE` in this codebase) is in `tasks/lessons.md` A174, not repeated here.

Status definitions: **Implemented** (verified in code AND covered by a meaningful test) · **Partial** (code exists but enforcement/integration/testing is incomplete) · **Missing** (no functional implementation found) · **Documented only** (described in docs, not in executable code).
