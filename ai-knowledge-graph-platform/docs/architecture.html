Architecture — as implemented

AI Knowledge Graph & Ontology Platform

A tenant-scoped platform for building, querying and reasoning over enterprise knowledge graphs. Documents and source records become provenance-bearing entities, claims, observations and relations in Neo4j; RDF/OWL/SKOS and SPARQL provide standards-based projections; bounded GraphRAG retrieves evidence for grounded answers; Context Graph records the decision trace.

Platform boundary: the core application, workers, graph, retrieval and governance paths are implemented and tested locally. External LLM providers, Neo4j, Redis, RabbitMQ, object storage and enterprise source connectors are deployment dependencies; the Energy POC demonstrates the RDF/SPARQL path with deterministic synthetic source-shaped records.

Evidence model
A graph fact is an auditable assertion

The platform deliberately separates a source statement from the conclusion an application or model may draw. This allows conflicting evidence to coexist, be reviewed and remain traceable.

Governance plane
Security and trust are structural

Access control, provenance, temporal state and agent capabilities are not post-processing. They shape what can be retrieved, written, explained and audited.

Isolation

Tenant-scoped by construction

Entities, edges, claims, conflicts, communities, cache keys, Context Graph traces and health snapshots carry tenant context. Unscoped access is rejected before execution.

Time + authority

As-of knowledge

Valid time and transaction time reconstruct point-in-time state. Regulatory, manufacturer, internal and informal sources are ranked by authority; superseded material is penalised.

Agent safety

Writes are governed

Tool calls pass policy, scope, risk, argument, timeout, dry-run and audit gates. High-risk operations support compensation paths and do not bypass the API boundary.

Dependency direction
From pure contracts to operational surfaces

The platform keeps domain contracts and graph semantics below the API, workers and dashboards. External services are replaceable infrastructure boundaries.

api/ + mcp_server/
FastAPI and authenticated MCP surfaces: validate identity, parse requests, call use cases and shape responses. No hidden tenant selection or bypass path.
graphrag/agents/ + business/
Answer policies, business objects, engineering workflows and governed write paths. Human review and operational actions remain separate from source evidence.
graphrag/retrieval/ + context_graph/
Hybrid retrieval, adaptive routing, answer cache, bounded Context Graph traces, decision manifests, policy evaluations and replay contracts.
graphrag/graph/ + ontology/
Neo4j execution, repositories, migrations, schema/indexes, type taxonomy, domain/range checks, inference, RDF/OWL/SKOS/PROV-O export and SPARQL bridge.
graphrag/ingestion/ + workers/
Adapters, parsing, chunking, reconciliation, entity resolution, async delivery, retries, visibility timeout, DLQ and worker health endpoints.
evaluation/ + monitoring/ + infra/
RAGAS, golden evaluations, calibration, chaos/failure harnesses, Prometheus metrics, OpenTelemetry, Docker Compose, Terraform and Kubernetes deployment surfaces.
External dependencies
Neo4j is the current graph runtime; Redis stores sessions/results/cache; RabbitMQ carries async work; optional TimescaleDB stores KPI events; LLMs/embeddings and object storage are provider boundaries.
