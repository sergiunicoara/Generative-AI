# Architecture, Security, and Production-Readiness Audit — 2026-08-21

## Executive assessment

The platform is a strong, test-rich GraphRAG and Context Graph implementation,
not a thin vector-search demo. It has tenant-scoped Neo4j access, formal RDF/
OWL/SHACL/SKOS interoperability, hybrid and graph retrieval, temporal and
provenance models, governed agent tools, asynchronous workers, replayable
decision traces, and production-oriented observability and deployment assets.

The audit found nine actionable cross-cutting gaps. All were remediated or
explicitly contained in this pass: durable broker topology, bounded API inputs,
safe error handling and publish rollback, deterministic resource shutdown, MCP
Origin enforcement, untrusted-context prompt boundaries, repository-wide lint
hygiene, dependency security, and live-test readiness. Known dependency
advisories fell from 72 across 16 packages to two no-fix advisories confined to
the optional RAGAS evaluation stack. Their reachable conditions and containment
are documented below.

The main remaining gap is evidence, not missing foundational code: production
load, chaos, recovery-time, and quality/cost ablations have not been run at a
representative customer scale. Do not market the project as customer-scale or
fully production-certified until those gates are measured.

## Findings and remediation

| Priority | Finding | Risk | Resolution |
|---|---|---|---|
| P1 | RabbitMQ queues and bindings existed only after consumers started | A valid API publish before worker startup could be accepted by the exchange and silently dropped | Every connection now idempotently provisions all durable exchanges, queues, DLQs, TTLs, and bindings; failed singleton connections are no longer cached |
| P1 | Expensive API fields and list/page controls were weakly bounded | Memory, token, graph, and queue resource exhaustion; invalid routing keys | Added global request-byte middleware plus field, collection, pagination, mode, and priority bounds |
| P1 | Internal exception text reached clients; query status was written before a publish that could fail | Information disclosure and permanently queued orphan jobs | Clients receive generic errors, internal details remain structured logs, and failed publishes delete the queued marker |
| P1 | API and worker shutdown omitted shared clients and trace flushing | Connection leaks, unflushed telemetry, and inconsistent restarts | Added shared lifecycle closure for RabbitMQ, Neo4j, Redis stores, health servers, and tracing |
| P1 | Remote MCP accepted arbitrary `Origin`; local default listened on all interfaces | DNS rebinding/cross-origin exposure and unnecessarily broad local reachability | Exact Origin allowlist enforcement; wildcard rejected; localhost default; container/Kubernetes bindings remain explicitly `0.0.0.0` |
| P1 | Retrieved/source text was concatenated into model prompts without an explicit trust boundary | Indirect prompt injection could influence extraction or answer behavior | Added explicit untrusted-data instructions and delimiters to ingestion, hybrid, and agentic prompts; tool policy remains the side-effect boundary |
| P3 | CI-targeted lint passed while repository-wide lint had 34 findings | Hygiene regressions outside selected runtime directories | All 34 findings fixed; repository-wide Ruff now passes |
| P1 | Locked dependencies contained 72 current advisories | Known exploitable dependency paths and stale reproducibility baseline | Replaced `python-jose` with PyJWT, raised patched security floors, constrained MCP to supported 1.x, regenerated the lock; two no-fix optional-evaluation advisories remain contained |
| P2 | Docker live tests used deprecated instance fixtures and a 120-second Neo4j cold-start timeout | False stalls/errors on Windows Docker Desktop and incomplete live evidence | Moved to module fixtures, pinned the project Neo4j line, and applied a bounded five-minute readiness gate; all seven live tests pass |

## Dependency residual risk

`pip-audit` reports two advisories without a released fixed version:

- `ragas==0.4.3`: SSRF in the multi-modal collections utility. This project
  does not import or configure multi-modal metrics; its evaluator allowlists
  faithfulness, answer relevancy, context precision, and context recall.
- `diskcache==5.6.3`: unsafe pickle deserialization if an attacker can write
  to its cache directory. It is pulled only by RAGAS. Evaluation workers must
  run as a non-root identity with a private, non-shared cache directory; no
  untrusted party may write that directory.

These are accepted, explicit residual risks because no fixed releases exist.
RAGAS remains an offline/isolated evaluation dependency and must not be exposed
as a generic user-selected metric or URL-fetching service. Remove or replace it
if either precondition cannot be guaranteed. The main API/query/ingestion
runtime does not require the evaluation subset in split container builds.

## Gap classification

### Good

- Tenant scope is propagated and defended at API, graph, and tool boundaries.
- Formal semantics are unusually complete: RDF export/import, OWL reasoning,
  SHACL validation, SKOS concept schemes, mappings, and hierarchy traversal.
- Knowledge state includes source provenance, confidence, contradiction,
  supersession, bitemporal snapshots, retention, and erasure workflows.
- Retrieval combines lexical, vector, graph, community, reranker, graph-neural,
  and bounded agentic signals instead of depending on one retrieval mode.
- Tests cover capability fallback, security boundaries, Context Graph replay,
  graph behavior, messaging, and Docker-backed integration paths.

### Acceptable, with an operating gate

- Prompt injection mitigation is defense in depth, not a proof of immunity.
  Keep side effects behind `ToolPolicy`, minimize tool scopes, and red-team
  indirect injection whenever prompts or tools change.
- Neo4j Community/single-instance deployment is adequate for current evidence,
  but clustering, read replicas, and online backups need Enterprise or managed
  deployment when SLOs require them.
- Fixed retrieval weights are supported by measured experiments, but should
  remain benchmark-driven per corpus; graph scores must complement text.
- MCP bearer validation is adequate for controlled deployment, while public or
  multi-issuer deployments require OAuth resource metadata and audience checks.

### Weak / not yet evidenced

- No representative 10x/100x/1000x load and cost report is checked in.
- No scheduled chaos test proves broker/database restart recovery and RTO/RPO.
- No GraphRAG-Bench-compatible cross-pipeline evaluation compares retrieval
  quality, answer quality, latency, and indexing cost on the same corpus.
- CI configuration in the parent monorepo still lints selected runtime folders
  rather than `ruff check .`; the repository is clean now, but the gate should
  be broadened at the parent workflow level.

## Scale analysis

| Scale | First pressure points | Required response |
|---|---|---|
| 10x | LLM quotas, reranker CPU, RabbitMQ queue age, Neo4j write contention | Horizontal workers by queue, autoscale on oldest-message age, batch writes, track p95/p99 and provider spend |
| 100x | Neo4j page cache/index memory, community rebuild duration, vector index growth, retry storms | Capacity-test graph memory, isolate rebuild jobs, introduce read replicas/managed cluster, enforce per-tenant quotas and backpressure |
| 1000x | Single graph/database blast radius, tenant hot spots, ingest artifact transfer, global recomputation | Partition tenants/workloads, object-store-backed ingest, independently scalable indexing, clustered/managed graph, regional DR and rehearsed restore |

The first bottleneck is likely external model throughput or reranking CPU for
queries, and Neo4j write contention/community maintenance for ingestion. That
is an evidence-based hypothesis from the architecture, not a measured capacity
claim; the roadmap requires load tests before sizing decisions.

## State-of-the-art comparison and decisions

| Reference | Useful idea | Project decision |
|---|---|---|
| Microsoft GraphRAG | Local/global search, community summaries, DRIFT, standard vs fast indexing choices | Local/global and bounded agentic behavior already exist. Benchmark DRIFT-style routing and fast extraction; do not copy defaults without quality/cost evidence |
| Neo4j GraphRAG | First-party vector, hybrid, Cypher, and tool-agent retrievers | Existing capability-gated vector/hybrid graph path is aligned; keep Neo4j execution plans and index statistics in performance reviews |
| LightRAG | Incremental dual-level retrieval with low indexing/query cost | Preserve as a benchmark candidate, not a migration target; this project prioritizes governed ontology and temporal/context semantics |
| HippoRAG | Personalized PageRank and memory-inspired multi-hop retrieval | Existing PageRank is a foundation; query-personalized PageRank is experimental until it beats current graph expansion on the golden sets |
| GraphRAG-Benchmark | Dataset/task/pipeline-level comparison | Build an adapter so changes are evaluated across quality, latency, and cost, not by anecdotal queries |

### Implemented now

- Durable broker topology and reconnect-safe singleton lifecycle.
- Request and domain-model bounds, safe publish rollback, and generic errors.
- Shared graceful shutdown and telemetry flush.
- MCP Origin allowlisting and least-exposure binding defaults.
- Untrusted-document prompt boundaries.
- Patched dependency floors, PyJWT migration, regenerated lock.
- Regression tests and repository-wide lint cleanup.

### Planned after this audit

- GraphRAG-Benchmark adapter and reproducible comparative report.
- DRIFT-style and personalized-PageRank ablations against current local/global/
  agentic routing, with quality, latency, token, and indexing-cost measures.
- OAuth 2.1 protected-resource metadata and audience/resource binding for
  federated remote MCP deployments.
- Representative load, retry-storm, broker restart, graph restart, backup, and
  restore drills with SLO/RTO/RPO evidence.
- OpenTelemetry GenAI semantic-convention alignment after the relevant fields
  used by this project are stable enough to avoid telemetry churn.
- Replace RAGAS if upstream does not release fixes for its SSRF/cache chain.

### Rejected for now

- Replacing the governed ontology/context model with LightRAG: loses semantics
  and governance without demonstrated benefit.
- Adding a second graph database such as Ultipa: duplicates operational state
  and consistency work without a measured requirement Neo4j cannot meet.
- Making agentic loops the default: increases latency, model spend, and attack
  surface; bounded fallback is safer.
- Choosing fast extraction or graph expansion solely because another project
  reports it as cheaper/faster: corpus-specific accuracy is the release gate.

## Verification gate

The audit is complete only when all of the following pass on the final tree:

- repository-wide Ruff;
- Python compile check for runtime packages;
- focused regressions for request limits, queue topology, lifecycle, MCP
  Origin policy, prompt boundaries, auth, query, and ingest behavior;
- complete pytest suite, including Docker-backed tests when services are
  available;
- Docker Compose configuration validation;
- dependency audit, with only the two documented no-fix evaluation advisories;
- secret-pattern scan and final diff review.
