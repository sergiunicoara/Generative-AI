# Full-project audit — 2026-09-23

A whole-repo audit run across security, correctness, tests/CI/dependencies,
and repo hygiene (four parallel review passes plus manual verification of
every finding against source before anything was accepted or fixed). This
file records what was found, what was fixed in this pass, and what is
deliberately left open with a reason.

**Automated checks run:** full unit suite (2484 passed, 0 failed after the
fixes below — 2471 before), `ruff check .` (clean), `pip-audit -r
requirements.lock` (flags `diskcache==5.6.3` / PYSEC-2026-2447 and
`ragas==0.4.3` / PYSEC-2026-3046 — not addressed here, see below).

Tests: `TestSemanticAnswerCacheKeyStability` in [test_hybrid_retriever.py](../../tests/unit/test_hybrid_retriever.py). |
| 8 | High | The project's own `.github/workflows/ci.yml` never ran — GitHub Actions only reads workflows from the *repository* root, and this repo's git root is the `Generative-AI/` monorepo, not this project directory. Real CI lives at `../.github/workflows/ai-knowledge-graph-platform-ci.yml`. This has already happened twice: added, correctly relocated to the repo root (`328f8fc`), then silently reintroduced with no comment (`f5dbf28`) — almost certainly a stale branch merge. | Deleted the dead file again. Added [tests/unit/test_repo_hygiene.py](../../tests/unit/test_repo_hygiene.py) asserting the in-project `.github/workflows/` directory doesn't exist and the real workflow does, so a third reintroduction fails CI instead of silently doing nothing. |
| 9 | High | `requirements.lock` didn't include `gremlinpython` (added to `requirements.txt` in a later commit than the lock was last regenerated), so a lock-based install breaks collecting `tests/unit/test_graph_backend.py`. | Regenerated `requirements.lock` via `pip-compile`. **Caveat, corrected during this fix:** regenerating on this (Windows) machine silently dropped the `; sys_platform == "win32"` marker from `pywin32`'s line — `pip-compile` doesn't cross-compile platform markers, it only reasons about the platform it's running on. Every fix above has an accompanying test that was verified to **fail against

fixed before landing.

## Correction to a sub-agent's finding (not fixed, because not real)

The tests/CI/dependencies review agent claimed `requirements/workers.txt`
(installed into the Fly `workers` app, entry point `workers/combined_worker.py`)
needs `aiohttp` because `graphrag/workers/health_server.py` imports it. Traced
the actual import graph: `combined_worker.py` only imports
`graphrag.messaging.consumers.{IngestionConsumer,QueryConsumer}`, neither of
which imports `health_server`. Only `workers/ingestion_worker.py` and
`workers/query_worker.py` import it directly, and their requirement files
(`requirements/ingestion.txt`, `requirements/query.txt`) already declare
`aiohttp` explicitly with a comment recording this exact class of bug. No
change made to `workers.txt` — the claim didn't hold up.

Also worth recording: the same agent's D3 finding ("`openai` isn't declared
anywhere") is wrong for `requirements/base.txt`, which does declare
`openai>=1.0.0` directly — the agent likely only checked the top-level
`requirements.txt`.

## Not fixed — Medium

- **Ingestion counter leak on failed ingest:** `active_updates` (incremented
  in `begin_corpus_update`) only comes back down on success — no
  try/finally. A failed ingest leaves it permanently elevated, and
  `updating=true` disables the answer cache for that tenant indefinitely.
  `graphrag/agents/ingestion_agent.py:225,371`. **Fix:** wrap in the
  existing `CorpusMutation` context manager (`graph/corpus_revision.py`).
- **Relation confidence inflates on re-ingest:** reconcile removes a
  document from `source_doc_ids` but not its contribution to
  `r.confidence`; the next merge treats the document as new and
  Bayesian-updates again — unbounded climb toward 1.0 on repeated
  re-ingests. `graphrag/graph/neo4j_client.py:1091-1103,1370-1374`.
- **A retry doesn't clean up the failed attempt's partial writes:**
  `is_reingest` is computed as `canonical_id != original_id`, which is
  False on a same-payload retry, so `reconcile_document_evidence` is
  skipped and a non-deterministic LLM's differing re-extraction can leave
  orphaned facts attributed to the document.
  `graphrag/agents/ingestion_agent.py:243`.
- **TTL-expired DLQ messages are refused by replay** and trigger the same
  requeue-loop shape #5 fixed (now safely terminates, but they're still
  never actually replayed): RabbitMQ dead-letters an expired message with
  its raw body and an `x-death` header, not the retry envelope
  `replay_dlq.py` expects, so it's treated as "written before replay
  support existed" and skipped forever. **Fix:** if there's no envelope but
  an `x-death` header is present, replay `message.body` as-is.
- **Degree-anomaly auto-quarantine quarantines nothing:** passes
  `entity_type="UNKNOWN"` to a lookup that matches on `{name, type,
  tenant}`, so it always misses — but still logs and returns as if it
  succeeded. `graphrag/graph/quarantine.py:226-233`.
- **Conversation history stores the pre-fallback answer:** `record_turn`
  runs before the agentic fallback can swap in a different answer, and is
  skipped entirely in `global` mode. `graphrag/retrieval/hybrid_retriever.py:796-908`.
- **An optional trace/eval-publish failure re-runs a completed query:**
  `_record_context_trace`'s Neo4j lineage query and `publish_eval_job` both
  run outside the fail-open `try` that the rest of the pipeline is guarded
  by, so a blip there re-runs the whole (already-paid-for) LLM pipeline up
  to 3 times via RabbitMQ retry.
- **A failed query is never marked `failed`:** the client polls `GET
  /query/{id}` and sees `queued` until the result-store TTL (3600s) expires,
  then gets a 404 with no error ever surfaced.
- **LLM SDK clients keep their default retries on top of the app's own
  retry loop:** `Groq(...)`/`OpenAI(...)` aren't constructed with
  `max_retries=0`, so `max_retries=1` at the app level still makes 3 HTTP
  attempts with SDK backoff — a stalled provider can cost ~180s before
  falling back. `graphrag/core/llm_client.py`.
- **KPI dashboard latency percentiles are biased low:** `ORDER BY
  latency_ms LIMIT 10000` computes p50/p95 over only the fastest 10k rows
  once a tenant exceeds that count. `graphrag/business_matrix/kpi_tracker.py:111-119`.
- **KPI quality averages are deflated:** uncomputed metrics default to
  `0.0` rather than `NULL` and get averaged in; only `faithfulness` is
  configured to compute at all. `evaluation_agent.py:201-222`.
- **Cache invalidation by entity name matches nothing:** the cache indexes
  entries under `citations` (document labels); `/kg/cache/invalidate` takes
  entity names, so it always reports `{"invalidated": 0}`.
- **Remote SPARQL endpoint isn't tenant-scoped:** once
  `GRAPHRAG_SPARQL_ENDPOINT` is configured, any caller with `read` scope
  can query every tenant's triples on the shared store.
- **External IdP tokens trusted with any tenant/scope claim:** no
  per-issuer `allowed_tenants` or max-scope limit on
  `TrustedIssuerConfig`.
- **Any tenant's admin can change the shared type taxonomy:**
  `MERGE (:EntityType)-[:SUBCLASS_OF]->` in `knowledge.py:124-135` has no
  tenant scoping.
- **`docker-compose.yml` binds data stores to `0.0.0.0`** with default or
  no credentials (Neo4j, Redis, RabbitMQ, Postgres, Grafana `admin/admin`).
- **`/admin` dashboard login has no rate limit** and compares the admin
  token with `==` instead of `hmac.compare_digest`.
- **GKE doesn't enforce the Kubernetes NetworkPolicies** — no
  `network_policy {}`/Dataplane V2 in Terraform, so
  `deploy/kubernetes/network-policy.yaml` is decorative; control plane is
  also public.
- **GremlinBackend unit tests never exercise real traversals** — `_submit`
  is mocked out entirely, so tenant filtering and the actual Gremlin
  bytecode are untested. ADR-0012 overstates this coverage.
- **Document-catalog API has unbounded `limit`/`offset`** and no
  pagination tie-breaker (added in commit `3be22f6`).

## Not fixed — Low / hygiene

- `diskcache==5.6.3` (PYSEC-2026-2447) and `ragas==0.4.3` (PYSEC-2026-3046)
  have known CVEs per `pip-audit` — not upgraded here (untested blast
  radius on the eval pipeline and caching layer).
- Auth cookie only gets `Secure` when `ENV=production` exactly (misses
  `staging`).
- Token revocation fails open (in-process memory) when Redis is down and
  `jwt_revocation_strict: false`.
- Production CORS check doesn't explicitly reject `"*"`.
- GDPR erasure needs only `write` scope, not `admin`.
- ~15 MB of `.mp4`/`.sqlite`/`.zip` binaries tracked in git under
  `docs/presentation/` and `artifacts/`.
- Scraped LinkedIn content (other people's names + full post text) tracked
  under `research/linkedin_group/` in an MIT-licensed public repo.
- `pika` is declared in `requirements.txt` and 4 subset files but imported
  nowhere (only `aio_pika` is used).
- `GeminiLLM`/`GeminiEmbedder` are dead code (never instantiated) and pull
  in `google-genai`/`google-generativeai` for nothing.
- README's testing section (`README.md:940-953`) says 794 unit tests / 5
  e2e files; actual counts are 2484 and 12.
- ~20 environment variables read in code aren't documented in `.env.example`
  (`GREMLIN_URL`, `WORKER_HEALTH_PORT`, `GRAPHRAG_SPARQL_*`, others).
- `docs/REMAINING_AUDIT_BACKLOG.md` item 7 still cites the now-deleted
  in-project `.github/workflows/ci.yml` as the workflow branch protection
  should require — needs updating to point at
  `ai-knowledge-graph-platform-ci.yml` at the repo root.

## Closure pass — 2026-09-25

Every "Not fixed" item above was re-verified against source; items 1–3, 5–10
(Medium) had already been closed in `be538c1`. The rest were closed here:

| Item | Resolution |
|---|---|
| KPI quality averages deflated | `EvalResult.computed_metrics` records what was actually scored; `KPIEvent` quality fields default to `None` and the columns are nullable, so `AVG()` skips unscored metrics instead of averaging in 0.0. |
| Cache invalidation matches nothing | Answer cache now indexes on `local_results["referenced_entities"]` (entity names, what `/kg/cache/invalidate` takes) instead of citation labels. |
| Remote SPARQL not tenant-scoped | `GRAPHRAG_SPARQL_ENDPOINT` supports a `{tenant}` placeholder (namespace per tenant); a placeholder-free shared endpoint serves only `GRAPHRAG_SPARQL_TENANT`, every other tenant gets 403. Chosen over named-graph scoping: the Blazegraph namespaces run in triples mode, and a query-rewrite scope can't be trusted against arbitrary user SPARQL. |
| External IdP tokens trusted for any tenant/scope | `TrustedIssuerConfig.allowed_tenants` (required at settings load) and `max_scopes` (closed allow-list); `tenant` claim and every `tenant:*`/other scope are checked at verify time. **Existing `JWT_TRUSTED_ISSUERS` config must add `allowed_tenants`.** |
| Any tenant's admin edits the shared taxonomy | Untagged `SUBCLASS_OF` edges are the platform hierarchy; `/kg/taxonomy/register` writes a `{tenant}`-tagged edge visible only in that tenant's expand/schema/entities views. Pre-existing API-registered edges (untagged) remain platform-wide. |
| `docker-compose.yml` on `0.0.0.0` | Every published port bound to `127.0.0.1`. Dev credentials left unchanged (loopback-only) — rotating them would lock existing local Neo4j volumes out. |
| GKE NetworkPolicy not enforced / public control plane | Terraform: Dataplane V2 (`ADVANCED_DATAPATH`), private nodes, `master_authorized_networks`, Cloud NAT. **Not applied or `terraform validate`d here** (no CLI/credentials); both datapath and private-cluster changes force cluster replacement. |
| Doc-catalog unbounded pagination | `limit` 1–500, `offset` 0–100000, `ORDER BY ingested_at DESC, id ASC`. |
| `/admin` login: no rate limit, `==` compare | Per-IP 5 failures / 5 min → 429; `X-Admin-Token` header now `compare_digest` too. Also fixed, found by the new test: an empty `GRAPHRAG_ADMIN_SECRET=` (as shipped in `.env.example`) gave Flask an empty session secret, so every successful login was a 500. |
| Low: cookie `Secure` only in `production` | `Secure` everywhere outside `DEV_ENVS`. |
| Low: revocation fails open | `jwt_revocation_strict` unset now means strict outside `DEV_ENVS`; explicit `false` still opts out. |
| Low: CORS `"*"` in production | Rejected; production origins must be `https://`. |
| Low: GDPR erasure on `write` | Now `admin`; the audit `requested_by` is the token `sub` (body value kept only as "on behalf of" note). |
| Low: tracked binaries / scraped LinkedIn data | Untracked + `.gitignore`d (files kept on disk). **History not rewritten** — still in past commits. `artifacts/energy-demo-sap.sqlite` stays tracked: it's a pinned fixture the API and `test_energy_demo.py` rely on. |
| Low: `pika`, `GeminiLLM`/`GeminiEmbedder` | Removed, with `google-genai`/`google-generativeai` from the service requirement subsets. |
| Low: README test counts, `.env.example` gaps | Updated; `.env.example`'s stale `GRAPHRAG_RDF_EXPORT_PATH` replaced with the real `GRAPHRAG_RDF_EXPORT_DIR`. |
| `_record_turn` unguarded (new, found during re-verification) | Session-history write is best-effort, like the trace write, so it can't requeue a completed query. |

**Still open:** `diskcache==5.6.3` / `ragas==0.4.3` CVEs — both are the latest
releases and pip-audit lists no fix version (`diskcache` arrives only via
`ragas`). GremlinBackend unit tests still mock `_submit`; the opt-in
`tests/e2e/test_live_gremlin.py` is the real-traversal coverage.

## Deliberately not attempted here

- **Live-infra verification** (Fly public IP exposure, whether GitHub
  branch protection actually requires the real CI workflow) — needs
  authenticated `flyctl`/`gh` access this environment doesn't have.
- **Dependency CVE remediation** — needs a full re-test pass against
  whatever `diskcache`/`ragas` version fixes the CVE; out of scope for an
  audit-fix pass with no live eval-pipeline access to validate against.
- **Full requirements-subset reconciliation** (D2/D4/D5 in the original
  hygiene report) — the two concrete, verified bugs (#9's gremlinpython gap)
  are fixed; the broader "regenerate every per-service subset from a single
  source" refactor is a real improvement but a separate, larger change with
  its own regression risk, not a same-session fix.
