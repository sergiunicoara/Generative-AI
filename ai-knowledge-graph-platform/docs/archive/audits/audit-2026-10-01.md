# Full-project audit — 2026-10-01

Scope: the whole repository at `46edd23` (CI green, unchanged since 2026-09-25),
excluding everything already recorded as fixed or known-open in
[audit-2026-09-23.md](audit-2026-09-23.md) and
[../../REMAINING_AUDIT_BACKLOG.md](../../REMAINING_AUDIT_BACKLOG.md).

Method: four parallel read-only review passes (security & tenant isolation;
data correctness; tests, CI & dependencies; repo hygiene & stale docs), each
required to open and trace the code for every finding. The dependency pass
simulated each Docker image by blocking every module outside that service's
resolved requirement subset and importing the real entry point. Findings marked
**verified** were then re-checked line-by-line in the main session; the rest are
as traced by the review pass (file:line given so they can be checked).

Nothing was fixed in this pass.

## Verdict

The application logic is in decent shape, but **the per-service container images
do not run**: the API image cannot import, the dashboard image cannot import, and
every worker image crashes on paid LLM calls. CI is green only because it installs
the monolithic `requirements.txt`, never the `requirements/${SERVICE}.txt` subsets
the Dockerfile actually uses. Separately, the remote MCP transport does not bind
sessions to callers, and two regressions came in with the 09-23/09-25 fix commits
(`be538c1`, `b2c7be1`).
