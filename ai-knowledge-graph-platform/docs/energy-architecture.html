Energy Asset Intelligence

Synthetic SAP, Snowflake and SharePoint-shaped records become an evidence-backed RDF graph. Governed publication, SPARQL retrieval, optional GraphDB and Neo4j projections, append-only maintenance workflow, and measured regression evidence demonstrate the complete tenant-scoped path.

Implemented POC path: deterministic SAP-shaped SQLite and Snowflake-shaped JSON → executed R2RML/RML mappings → candidate RDF → SHACL quarantine/publication → SPARQL advisory → governed review workflow and UI. Published RDF can be served from a tested local GraphDB path and projected one-way into a rebuildable Neo4j read model. The data is synthetic; live enterprise connectors, production hosting and source-system writes remain extension work.

Anatomy of an advisory answer
A maintenance recommendation carries its proof

The UI does not present a free-floating AI claim. It renders the decision alongside the current rule, observed value, open work context, source identifiers, and the query that combined them.

Safety boundaries
Useful advice without pretending to be a control system

The POC makes the intended decision boundary explicit. It is designed to earn review confidence, not to bypass operations governance.

Temporal correctness

Rules change over time

The historical scenario selects R1 at 90 °C before 1 June 2026 and R2 at 85 °C after that date. A recommendation has an effective-date context.

Evidence discipline

Unknown stays unknown

Assets with no sufficient telemetry are surfaced as evidence gaps. The system requests further evidence rather than fabricating maintenance risk.

No maintenance conclusion without evidence
Human control

Advisory, not autonomous

The workspace identifies a review priority. Explicit authenticated actions can advance the local review lifecycle, but the POC does not command equipment or mutate SAP.

Layering
Dependency direction and operational responsibility

The serving layer stays thin. RDF materialisation, semantic querying, validation, and answer construction are separated from the API and presentation layer.

api/routes/energy_demo.py
Tenant-gated routes expose the dashboard, questions, answer, RDF export, and validation result. It shapes responses; semantic logic lives below it.
graphrag/domains/energy/demo.py
Deterministic EnergyDemoService: materialises source-backed RDF, selects the applicable bulletin, executes the committed query and assembles evidence-backed advisory responses.
graphrag/domains/energy/publication.py
Versioned publication boundary: stages candidate RDF, applies the real SHACL validator, quarantines invalid records, publishes the conformant graph and supports append-only rollback.
graphrag/domains/energy/lpg_projection.py
Fail-closed, one-way projection from authoritative published RDF into a tenant-scoped, rebuildable Neo4j read model for traversal and GraphRAG.
graphrag/domains/energy/workflow.py
Local governed work-order lifecycle with legal transitions, actor/reason evidence, immutable history and an RDF projection separate from source facts.
ontology/models/energy-asset-intelligence.yaml
Authoritative storage-independent model. graphrag/semantic_model/ validates it and deterministically emits OWL/RDFS, SHACL, Neo4j constraints, and typed loss diagnostics. --check gates artifact drift.
graphrag/ingestion/graph_writer.py
For compiled LPG domains, the shared write path accepts an injected semantic mutation validator and rejects abstract nodes, missing or unknown properties, invalid datatypes, and invalid relationship endpoints before a Neo4j mutation.
ontology/mappings/energy-assets.r2rml.ttl + energy-observations.rml.ttl
Executed mapping contracts for relational assets/work orders and JSON telemetry. They transform source records into RDF and remain separate from generated ontology/database schemas.
evals/energy_demo/sparql/maintenance_review.rq
Version-controlled semantic query that retrieves the affected asset, observed temperature, authoritative threshold, bulletin and open work order.
scripts/run_energy_demo_e2e.py
Repeatable proof path: creates synthetic sources, materialises and publishes RDF, executes the SPARQL advisory, proves temporal selection, abstention and tenant isolation, exports Turtle, and builds governed Neo4j projection batches. --live-neo4j is an explicit opt-in database write.
scripts/build_energy_evaluation_report.py
Produces a versioned local evidence report for fixed answers, evidence accuracy, abstention, tenant isolation, freshness, p95 answer latency and small-fixture materialisation throughput.
tests/unit/test_energy_* + tests/e2e/test_live_graphdb.py
Regression coverage spans mappings, publication, rollback, workflow, evaluation, LPG projection and API behavior. The Docker-backed GraphDB suite verifies repository creation, load, SPARQL query, restart persistence and portable RDF recovery.
