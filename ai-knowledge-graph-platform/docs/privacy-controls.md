# Privacy controls

Implemented 2026-11-03. Verified with unit tests that run offline (in-memory
caches, temporary SQLite, in-memory rdflib datasets, fake connectors, mocked
Neo4j drivers). Nothing here was exercised against a live Neo4j, Redis, triple
store, SharePoint tenant or model provider.

## Erasure and correction propagation

`graphrag/graph/erasure_registry.py` lists every place a fact can live after it
is written and what an approved erasure does there. `GDPRService.forget_entity`
now also clears the entity's media attachments and cached embeddings, and its
log line records a digest instead of the erased name.
`KnowledgeEvaluationService.erase_subject` redacts a subject's facts and
identity from the decision log and their trust reports and evicts the tenant's
cached decisions; `named_graphs.erase_resource` removes a resource from one
tenant's named graphs; `LLMCache.purge` empties the on-disk extraction cache.

| Store | Holds | Coverage | Handler or rule |
| --- | --- | --- | --- |
| neo4j.entity | entity node, its edges, statements and change log | erased | `graphrag.graph.gdpr:GDPRService.forget_entity` |
| neo4j.chunk_text | chunk text mentioning the entity | redacted | `graphrag.graph.gdpr:GDPRService.forget_entity`; exact-name matches become [REDACTED]; aliases and pronouns are not caught |
| neo4j.entity_embeddings | entity vectors | erased | `graphrag.graph.gdpr:GDPRService.forget_entity`; removed with the entity node |
| neo4j.chunk_embeddings | chunk vectors | not_covered | vectors of redacted chunks are not recomputed; re-embed redacted chunks after erasure |
| neo4j.community_summaries | community summaries and their vectors | not_covered | regenerated on the next community rebuild, not rewritten on erasure |
| neo4j.aliases | alias nodes and the alias fulltext index | not_covered | alias nodes naming the entity are not deleted by the erasure |
| neo4j.media | media attachments of the entity | erased | `graphrag.graph.multimodal:MultiModalEntityService.delete_entity_media`; called from GDPRService._erase_derived |
| cache.embeddings | in-process embedding cache | erased | `graphrag.graph.embedding_cache:EmbeddingCache.invalidate`; called from GDPRService._erase_derived |
| cache.answers | query answer cache (raw chunk contexts) | erased | `graphrag.retrieval.query_cache:QueryCache.flush_tenant`; flushed after erasure; the corpus revision bump makes old keys unreachable first |
| redis.result_store | async query results by query id | expires | time to live 3600 s; no tenant-wide purge |
| redis.sessions | conversation sessions | expires | time to live 24 h |
| knowledge.decision_cache | cached knowledge decisions | erased | `graphrag.context_graph.knowledge_service:KnowledgeEvaluationService.evict_tenant` |
| knowledge.decision_log | decision records with submitted facts and caller identity | redacted | `graphrag.context_graph.knowledge_service:KnowledgeEvaluationService.erase_subject`; facts and identity are removed; the record of a decision stays and no longer replays |
| knowledge.trust_reports | distrust reports with their bundles | redacted | `graphrag.domains.energy.governance_store:GovernanceStore.redact_knowledge_decisions`; the reporter's identity and submitted facts are removed |
| knowledge.releases | published knowledge releases | immutable | curated knowledge, not personal data by contract; a correction is a new release, history is kept for replay |
| energy.governance | Energy publications, workflow and evidence history | immutable | append-only governance history holding actor ids only |
| energy.rdf_blobs | content-addressed RDF blobs | immutable | shared by digest; a correction is a new publication |
| rdf.exports | per-tenant Turtle exports | not_covered | regenerated by scripts/export_rdf.py; re-export after erasure |
| rdf.named_graphs | triple-store named graphs (ADR-0013) | erased | `graphrag.graph.named_graphs:erase_resource`; per resource within one tenant; drop_tenant for all |
| cache.llm_extraction | on-disk prompt/response cache (opt-in) | erased | `graphrag.core.llm_cache:LLMCache.purge`; no tenant key, so the purge empties the cache |
| logs.structured | application logs | redacted | the erasure log line records a digest, not the name; other lines follow log retention |
| audit.deletion | DeletionAudit nodes | immutable | keep the erasure's own audit record (who, when, counts); documented exception |
| audit.capabilities | capability audit events | immutable | arguments are stored as a hash only |
| context_graph.traces | decision traces | redacted | `graphrag.context_graph.repository:ContextGraphRepository.redact_trace`; appends a redaction marker; retention policy applies |

Stores marked `not_covered` are known gaps, stated so they are not mistaken for
coverage: chunk vectors are not recomputed after redaction, community summaries
are only rewritten on the next rebuild, alias nodes are not deleted, and Turtle
exports must be regenerated after an erasure.

## Data minimisation before model providers

`graphrag/core/outbound.py` runs inside `FallbackLLM.generate` (what `get_llm`
and `get_fast_llm` return) and `OpenAIEmbedder.embed` (`get_embedder`), using
the tenant from the request's tenant context (ingestion now sets it for each
document). Per tenant (`config/outbound_policy.yml`): external providers can be
disabled (the call raises `OutboundDisabledError` and the provider is never
called), direct identifiers are redacted by pattern (e-mail, phone, SSN and IP
addresses by default), and structured records can be cut to a field allowlist.
What was sent is audited as SHA-256 and size only. Pattern-based redaction is
incomplete by nature: names and identifiers without a recognisable shape are
not caught. Clients constructed directly (a bare provider client, the optional
RAGAS evaluator) are not covered.

## Extraction record contract

Every extracted entity and relation keeps its source chunk, the model that
actually answered, the prompt version (now derived from the prompt template,
`PROMPT_VERSION`), a confidence and a `review_state`: `accepted`, `uncertain`
(relation confidence below `EXTRACTION_REVIEW_CONFIDENCE`, default 0.6) or
`unsupported` (the name does not occur in the source text). Only accepted
assertions reach the graph; the others go to the review quarantine with their
full record (`ENT-REVIEW-001`, `REL-REVIEW-003`). `extraction_records` and
`diff_extraction_records` make two runs, for example with different models,
diffable.

## Permission freshness

A restricted document's ACL records when it was read from its source
(`DocumentAccessPolicy.observed_at`, stamped by the SharePoint connector).
Retrieval (the Cypher predicate) and the Python mirror deny a restricted
document whose ACL is older than `ACL_MAX_AGE_SECONDS` (default 3600). The
answer-cache key includes the ACL window (`acl_epoch`), so answers built while
a document was readable stop being served when the window turns over. Stated
bound: a revocation that is re-synced takes effect on the next request (the
re-ingest advances the corpus revision); one that never reaches the platform
stops affecting answers within at most twice `ACL_MAX_AGE_SECONDS`. A
permission source that cannot be reached yields an unknown ACL, which is
denied, and an audit record (`SharePointSyncConnector.acl_audit`, plus a log
event). Policies stored without an observation time (older corpora) are not
subject to the bound until they are re-synced. Knowledge-item ACLs are frozen
in their release: changing one needs a new release.
